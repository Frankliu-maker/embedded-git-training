## 一、环境搭建

- **安装 Git**：整个过程耗时约 40 分钟，速度较慢，建议在稳定的网络环境下进行。
- **初始配置**：安装完成后，按照文档指引依次执行 `git config` 命令完成用户名与邮箱的绑定。
  - 踩坑记录：初次配置时误将邮箱字段填写为用户名，重新修正后配置成功。
  - 建议配置完成后使用 `git config --list` 复核，避免因配置错误导致提交记录身份异常。

## 三、核心概念

Git 的文件流转分为四个层次，理解它们的边界是掌握版本控制的关键：

| 区域 | 说明 | 对应操作 |
| :--- | :--- | :--- |
| **工作区** | 日常编写、修改代码的地方 | 直接编辑文件 |
| **暂存区** | 待提交内容的临时存放区 | 点击 `+` 号或执行 `git add` |
| **本地仓库** | 保存已提交的版本历史 | 点击 `✓` 或执行 `git commit -m "提交信息"` |
| **远程仓库** | 托管在云端的代码仓库（如 GitHub） | 点击推送或执行 `git push` |

> 数据流向：**工作区 →（add）→ 暂存区 →（commit）→ 本地仓库 →（push）→ 远程仓库**

## 四、GitFlow 工作流认知

| 分支 | 定位 | 说明 |
| :--- | :--- | :--- |
| `main` / `master` | 稳定主干 | 存放对外发布的正式版本，始终保持可部署状态 |
| `dev` | 开发主干 | 团队日常集成与开发的主分支 |
| `feature` | 功能分支 | 由开发人员在本地创建，功能完成后合并进 `dev` 并删除 |
| `release` / `hotfix` | 发布与修复 | `release` 用于发布前的测试与回归；`hotfix` 用于线上问题的紧急修复 |
